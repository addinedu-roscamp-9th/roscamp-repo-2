[User GUI]
   ↓ (목적지 선택)
[FastAPI Server]
   ├─ 명령 큐(DB)
   ├─ 상태 DB
   ├─ 이벤트 로그
   └─ 정책 판단(배터리)
        ↓
[Pinky Supervisor FSM]
   └─ Nav2 실행


서버가 판단자

핑키는 실행자

GUI는 서버만 봄

2️⃣ Pinky 쪽: pinky_supervisor_fsm.py
역할

서버 명령 큐를 계속 폴링

명령은 항상 하나씩만 실행

이동 중에는 새 명령 시작 ❌

Nav2 이동 → DONE / FAILED ACK

상태를 주기적으로 서버에 업로드

중요한 개선점

❌ 1명령 후 멈추던 구조 제거

✅ 무한 소비자 구조

✅ 연속 명령 처리 가능

3️⃣ Server 쪽 (FastAPI)
역할

명령 큐 관리 (PENDING → CLAIMED → DONE/FAILED)

핑키 상태 저장 (pinky_state_current)

이벤트 로그 저장

GOTO 완료 시 배터리 판단 로직 존재

배터리 정책 (구조에 포함됨)

임계치: 30%

서버가 판단해서 다음 명령을 큐에 넣는 구조

GOTO_CHARGE (충전구역)

GOTO_IDLE (대기구역)

✔ 지금은 서버 쪽 자동 분기 로직까지 들어갈 수 있는 구조 완성
✔ 핑키 FSM은 그냥 서버 명령만 수행

4️⃣ 좌표 정책 (확정)

충전 구역

x = -0.025

y = 0.308

yaw = 0.0

대기 구역

x = 0.0

y = 0.0

yaw = 0.0

5️⃣ DB 구조
핵심 테이블

pinky_command_queue

pinky_state_current

event_log

상태 흐름

명령 생성 → CLAIM → DONE/FAILED

상태/배터리/목표 좌표 실시간 저장

👉 DB 저장은 정상 작동 중 (로그로 검증 완료)

6️⃣ 지금 시점에서 “배터리 모드 넣은 상태냐?”
답: 구조적으로는 이미 넣어 둔 상태입니다.

✔ 배터리 값 → 서버로 올라감

✔ 서버가 배터리 기준 판단 가능

✔ 충전/대기 명령 타입 준비됨

⏳ 서버 자동 분기 로직을 더 다듬으면 완성

즉,

“배터리 모드를 얹을 수 있는 구조까지 완료”
(나중에 이어서 바로 구현 가능)

7️⃣ 나중에 이어서 할 것 (정리)

서버에서 GOTO DONE 시 자동으로

GOTO_CHARGE / GOTO_IDLE 큐잉

사용자 GUI에서

시작 / 결제 / 돌아가기 → 서버 이벤트 연결

관리자 GUI에서

Status / Timeline 실시간 확인

한 줄로 끝내면

“서버 중심 FSM 구조 + 핑키 무한 명령 소비 + 배터리 판단 구조까지 깔아놓은 상태”

이 상태 그대로 두고 며칠 뒤에 와도 바로 이어서 가능합니다.
